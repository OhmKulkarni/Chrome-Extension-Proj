📊 Understanding Size Metrics

🤔 Why Your Size Numbers Make Perfect Sense!

Your example:

  • Transfer Size: 302 B - Total bytes over the network
  • Encoded Body Size: 2 B - Response body (compressed)
  • Decoded Body Size: 2 B - Response body (uncompressed)

This is completely normal! The difference comes from HTTP headers.

Typical HTTP Headers include:

  • Status line: HTTP/1.1 200 OK
  • Date, Server, Content-Type, Content-Length
  • Cache-Control, ETag, Last-Modified
  • Security headers (CORS, CSP, etc.)
  • Cookie headers

Headers easily add 200-400 bytes to any request!

📋 Common Size Scenarios

Scenario Transfer Size Body Size Explanation
API Health Check 300-400 B 2-20 B Tiny response ("OK"), large headers
JSON API Response 800-1200 B 400-800 B Headers + JSON data
Image (Small) 5-10 KB 4.5-9.5 KB Binary data, minimal headers
Compressed HTML 2-5 KB 1.5-4.5 KB GZIP compression saves space
Large JSON (Compressed) 15 KB 12 KB encoded, 40 KB decoded Heavy compression on text data

🔍 What to Look For

✅ Normal Patterns:

  • Transfer > Encoded ≥ Decoded
    Headers add to transfer size
  • Encoded ≤ Decoded
    Compression reduces encoded size
  • Small responses: Headers dominate
    (90% headers, 10% content)
  • Large responses: Content dominates
    (20% headers, 80% content)

🚩 Suspicious Patterns:

  • Encoded > Decoded
    Unusual compression artifact
  • Transfer < Encoded
    Data inconsistency
  • All zeros
    Cross-origin timing restriction
  • Huge transfer, tiny body
    Excessive headers or cookies
